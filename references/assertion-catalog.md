# 断言目录：动态业务数据的可验证真值

| 断言类型 | 要回答的问题 | 例子 |
| --- | --- | --- |
| 页面契约 | 用户能否看见并完成操作 | 退款记录出现、错误提示可读、按钮受角色控制 |
| 接口契约 | 调用语义是否正确 | 必填参数、业务码、字段格式、关联业务键 |
| 状态机 | 流转是否合法 | `PENDING → PAID → REFUNDING → REFUNDED` |
| 前后差值 | 变化量是否正确 | `after.refunded = before.refunded + 30` |
| 守恒/对账 | 金额、库存是否一致 | 子项合计等于主项；借贷合计为 0 |
| 关联完整性 | 数据是否跨表/跨服务一致 | 退款记录关联真实订单和流水 |
| 幂等/并发 | 重试是否重复产生效果 | 相同幂等键只产生一笔退款 |
| 边界/属性 | 规则是否覆盖输入组合 | 金额大于 0 且不超过实付；结束时间不早于开始时间 |
| 差分对照 | 改造是否改变结果 | 同一快照下新旧输出归一化后相同 |

固定夹具适合每个 PR；已脱敏、带来源时间和 schema 版本的快照适合复杂历史场景；生产灰度/影子验证只用于发现漏网组合，不能替代离线回归。动态 UUID、订单号和时间要检查格式、关系、范围或前后差值，而不是把某次运行值写死。
