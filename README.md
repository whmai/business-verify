# Screenshot-Guided Business Verification

将需求、测试人员提供的**文字操作说明、截图与业务预期**，转为可审阅、可执行、可回归的界面业务验证 Skill。

它并不把“再点一遍页面”误当作测试完成。它要求 AI 写出并执行专业测试人员真正会做的步骤：从哪个入口进入、看见什么、点什么、输入什么、跳到哪里交叉复核、接口要返回什么、数据规则如何证明正确。

## 核心流程

```text
需求
        ↓
AI 先生成“指导测试验证集”
        ↓ 人工确认关键业务口径
需求/文字步骤/截图补充到案例
        ↓
隔离数据 + UI 操作 + API/数据断言
        ↓
可审计报告 + 自动化回归资产
```

## 没有截图也能用

截图可帮助 AI 识别页面和留下证据，但不是前提。只有需求也可以使用：Skill 会先将每条需求映射为案例，并按“入口 → 观察 → 操作 → 即时预期 → 跨页面复核 → 接口/数据验证”的顺序，写成测试人员可以逐步照做的文字案例。随后 AI 以这份验证集为实现和自测门禁。缺少页面或接口信息时，明确标为待确认，而不是杜撰。

从需求开始的模板见 [需求到验证集模板](references/requirements-to-verification-set.md)；补充人工操作细节可使用 [文字优先案例模板](references/text-first-case-template.md)。

## 安装

复制整个目录到支持 Agent Skills 的位置，例如 Codex 项目中的：

```text
.codex/skills/business-verify/
```

必须保留 `SKILL.md` 和 `references/` 的相对目录结构。

## 示例提示

```text
Use $business-verify.
根据下面的需求和文字说明，为“部分退款”生成一份拟人化界面验证案例。
环境为 staging，可创建隔离测试订单；订单号和时间戳是动态字段。
先只输出测试契约，不执行操作，等待我确认金额、状态机和接口断言。
```

## 安全与质量边界

- 默认不在生产环境写入数据。
- 证据、截图、接口响应和数据快照必须最小化并脱敏。
- LLM 可以解释页面和生成草稿，不能成为金额、权限、状态机的唯一裁判。
- 页面改版造成自动化定位失败时，应报告并复核，不能悄悄放宽断言。

## 贡献
